# OctoAcme Project Management Documentation

## Welcome

OctoAcme runs projects using a structured, customer-focused approach that emphasizes clear ownership, iterative delivery, and data-informed decisions. This documentation center provides guidance for all team members on how we plan, execute, and improve our projects.

## Core Principles

- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has a named PM and Product Lead
- **Data-informed**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

## Project Lifecycle Overview

OctoAcme projects follow a structured five-phase lifecycle:

1. **Initiation**: Validate business need, align stakeholders, and confirm go/no-go decision
2. **Planning**: Break work into shippable increments, estimate scope, and identify dependencies
3. **Execution**: Build, test, review, and iterate on features with daily standup cadence
4. **Release**: Deploy to production following standardized pre-release and deployment checklists
5. **Close & Retrospective**: Capture learnings and convert them into actionable improvements

## Key Artifacts & Activities

- **Project One-pager**: Problem statement, goals, success metrics, stakeholders, timeline, risks, and team roles
- **Risk Register**: Centralized tracking of identified risks with impact, likelihood, owner, and mitigation plans
- **Project Board**: GitHub Projects with columns (Backlog, Ready, In Progress, In Review, QA, Done)
- **Backlog Items**: Prioritized features/tasks with acceptance criteria, estimates, and owners
- **Weekly Syncs**: PM + PdM alignment, delivery team standups, and stakeholder updates
- **Retrospectives**: Team reflection sessions to identify improvements and track action items

## Core Roles

- **Project Manager (PM)**: Coordinates delivery, manages schedules, risks, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes backlog, and measures success
- **Developers**: Implement features, write tests, and collaborate on design and testability
- **QA/Testing**: Validate quality and acceptance criteria
- **Stakeholders**: Provide inputs, approvals, and strategic alignment

*For detailed role definitions, see [Roles and Personas](octoacme-roles-and-personas.md)*

## Communication Cadence

| Cadence | Participants | Purpose |
|---------|--------------|---------|
| Daily | Delivery team | 15-min standup: progress, blockers, dependencies |
| 2x weekly | Delivery team | Extended standup if needed |
| Weekly | PM + PdM | Alignment, priorities, risks, roadmap |
| Weekly | Stakeholders | Status updates on progress, risks, ask/decisions |
| Monthly | Sponsor + Stakeholders | Strategic updates and milestone reviews |
| Sprint/Milestone | Full team | Demo/Review of completed work |
| Post-sprint/Release | Full team | Retrospective and action item planning |
